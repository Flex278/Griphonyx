# Модуль Интегрированного Планирования Пути — README

## Обзор
Данный документ описывает интеграцию между обнаружением препятствий и планированием пути для создания надёжной системы навигации автономных транспортных средств. Система использует данные с датчиков LiDAR, обрабатывает их через модуль обнаружения препятствий и применяет интегрированный планировщик для определения оптимальных путей для аппарата.

## Архитектура системы
Иллюстрация потока данных в системе:
(LiDAR) --> (Обнаружение препятствий) --> (Мост карты препятствий) --> (Интегрированный планировщик) --> (PX4)

## Мост PX4 (MAVLink)

Узел `px4_mavlink_bridge` подписывается на топик `/planned_path`
(`nav_msgs/Path`, кадр ENU `map`), который публикует `integrated_planner_node`,
конвертирует путевые точки в миссию PX4 и выполняет полёт в режиме `AUTO`.

### Последовательность работы
1. Принимает путь и переводит его из ENU в глобальные координаты
   (широта/долгота) относительно home-позиции PX4.
2. Загружает миссию по MAVLink: взлёт → `NAV_WAYPOINT` на каждую точку пути →
   посадка (`NAV_LAND`).
3. Армирует аппарат, переключает в режим `AUTO` (mission) и запускает миссию.

### Предварительные условия
- PX4 SITL запущен в контейнере `px4_gazebo` (Gazebo Classic), MAVLink-порт `14540`.
- В контейнере `ros2_px4_dev` установлен `pymavlink`:
  ```bash
  docker exec ros2_px4_dev bash -lc 'pip install pymavlink'
  ```

### Запуск
```bash
./scripts/run_px4_demo.sh
```
Скрипт синхронизирует пакет в контейнер, пересобирает его и запускает
`ros2 launch integrated_planning px4_demo.launch.py` (мост карты препятствий,
интегрированный планировщик, демо-драйвер и мост PX4).

### Параметры узла `px4_mavlink_bridge`
| Параметр            | По умолчанию           | Описание                                |
|---------------------|------------------------|-----------------------------------------|
| `connection_url`    | `udpin:127.0.0.1:14540` | Строка подключения pymavlink          |
| `takeoff_altitude`  | `0.0`                  | Высота взлёта, м (0 = первая точка пути)|
| `cruise_speed`      | `0.0`                  | Скорость полёта, м/с (0 = по умолчанию) |
| `acceptance_radius` | `1.0`                  | Радиус принятия путевой точки, м        |
| `add_land`          | `True`                 | Добавить посадку в конце миссии         |
| `fly_once`          | `True`                 | Выполнить только первый полученный путь |

Статус моста публикуется в топик `/bridge_status` (`std_msgs/String`).

## Конфигурация
### Параметры аппарата
- `vehicle_width`: Ширина аппарата в метрах.
- `max_speed`: Максимальная скорость аппарата в метрах/секунду.

### Параметры планирования
- `planning_horizon`: Длина горизонта планирования в секундах.
- `obstacle_buffer`: Буферное расстояние от обнаруженных препятствий в метрах.

## Топики ROS2
| Имя топика          | Тип           | Направление |
|---------------------|---------------|-------------|
| /obstacle_detection | sensor_msgs/LaserScan | Подписка    |
| /path_planning      | nav_msgs/Path      | Публикация   |

## Примеры использования
### Базовое планирование пути
Для запуска простого сценария планирования пути:
```bash
$ ros2 service call /path_planning <данные_запроса>
```
### Интеграция с ROS2
Интегрируйтесь с другими узлами ROS2 для расширения функциональности:
- Используйте вывод `/obstacle_detection` для влияния на решения планирования пути.
### Динамическое перепланирование
Перепланируйте пути динамически на основе изменяющихся препятствий, подписываясь на соответствующие события.
