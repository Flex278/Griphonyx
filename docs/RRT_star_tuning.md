# Руководство по настройке кинодинамического планировщика RRT*

Краткий справочник по настройке параметров планировщика RRT* для различных сценариев и миссий.

## Обзор параметров

| Параметр | По умолчанию | Диапазон | Влияние |
|-----------|---------|-------|--------|
| `max_iterations` | 2000 | 500-5000 | Качество планирования против времени вычислений |
| `step_size` | 5.0 м | 2.0-10.0 м | Детализация дерева и гладкость пути |
| `goal_tolerance` | 3.0 м | 1.0-5.0 м | Радиус принятия цели |
| `search_radius` | 15.0 м | 5.0-30.0 м | Качество оптимизации пути |
| `planning_horizon` | 100.0 м | 50.0-200.0 м | Дистанция взгляда вперёд |
| `min_turn_radius` | 20.0 м | 10.0-40.0 м | Ограничение резкости поворота |
| `obstacle_clearance` | 3.0 м | 2.0-5.0 м | Запас безопасности |
| `max_climb_angle` | 20.0° | 10.0-30.0° | Предел вертикального манёвра |
| `replan_rate` | 1.0 Гц | 0.5-5.0 Гц | Частота перепланирования |

## Конфигурации по сценариям

### 1. Открытая наружная навигация (редкие препятствия)

**Сценарий:** Дальняя навигация по путевым точкам с малым количеством препятствий

```yaml
max_iterations: 1000          # Меньше требуется для разреженных сред
step_size: 8.0               # Большие шаги допустимы в открытом пространстве
goal_tolerance: 5.0          # Ослабленный допуск для путевых точек
search_radius: 20.0          # Возможна большая оптимизация
planning_horizon: 150.0      # Смотреть дальше вперёд
min_turn_radius: 25.0        # Можно использовать более пологие повороты
obstacle_clearance: 3.0      # Стандартный просвет
max_climb_angle: 15.0        # Пологие наборы высоты для эффективности
replan_rate: 0.5             # Менее частое перепланирование
```

**Ожидаемая производительность:**
- Время планирования: ~50-150 мс
- Качество пути: 102-105% от оптимального
- Использование ресурсов: 25-30%

---

```yaml
step_size: 3.0               # Меньшие шаги для точности
goal_tolerance: 2.0          # Более жёсткое достижение цели
search_radius: 12.0          # Сфокусированная оптимизация
planning_horizon: 80.0       # Более короткий горизонт в загромождении
min_turn_radius: 18.0        # Более резкие повороты при необходимости
obstacle_clearance: 4.0      # Дополнительная безопасность в загромождении
max_climb_angle: 25.0        # Больше вертикальной свободы
replan_rate: 2.0             # Более частое перепланирование
```

**Ожидаемая производительность:**
- Время планирования: ~200-400 мс
- Качество пути: 105-110% от оптимального
- Использование ресурсов: 35-45%

```yaml

max_climb_angle: 15.0        # Плавные манёвры

```

**Ожидаемая производительность:**
- Время планирования: ~100-250 мс
- Качество пути: 108-112% от оптимального
- Использование ресурсов: 30-35%

**Примечание:** `danger_distance` следует увеличить до 120-150 м для высокоскоростного полёта.

**Сценарий:** Внезапное обнаружение препятствия, избегание столкновения

**Ожидаемая производительность:**

- Качество пути: 110-120% от оптимального (субоптимально, но безопасно)
- Использование ресурсов: 30-40%

**Триггер:** При обнаружении препятствия на расстоянии ближе 2× `min_turn_radius`.

## Рекомендации по настройке параметров

### Повышение качества планирования
1. ↑ `max_iterations` (2000 → 3000)
2. ↑ `search_radius` (15.0 → 20.0)
3. ↓ `step_size` (5.0 → 3.0)

**Цена:** Более долгое планирование, выше загрузка ЦП

### Сокращение времени вычислений
1. ↓ `max_iterations` (2000 → 1000)
2. ↓ `search_radius` (15.0 → 10.0)
3. ↑ `step_size` (5.0 → 7.0)

**Цена:** Менее оптимальные пути, могут быть проблемы в узких пространствах

### Улучшение гладкости пути
1. ↑ `search_radius` (15.0 → 20.0)
2. ↑ `min_turn_radius` (20.0 → 25.0)
3. ↓ `max_climb_angle` (20.0 → 15.0)

**Цена:** Требуется больше пространства для манёвра

### Работа в узких пространствах
1. ↓ `min_turn_radius` (20.0 → 15.0)
2. ↓ `step_size` (5.0 → 3.0)
3. ↓ `obstacle_clearance` (3.0 → 2.5) *только если безопасно*

**Цена:** Менее гладкие пути, выше вычислительная нагрузка

## Стратегии адаптивных параметров

### Адаптация по скорости

```python
# Псевдокод адаптивных параметров
if vehicle_speed < 10 м/с:
    min_turn_radius = 15.0
    planning_horizon = 60.0
    obstacle_clearance = 2.5
elif vehicle_speed < 20 м/с:
    min_turn_radius = 20.0
    planning_horizon = 100.0
    obstacle_clearance = 3.0
else:  # Высокая скорость
    min_turn_radius = 35.0
    planning_horizon = 150.0
    obstacle_clearance = 5.0
```

### Адаптация по окружающей среде

```python
# Псевдокод на основе плотности препятствий
obstacle_density = count_obstacles_in_horizon() / planning_volume

if obstacle_density > 0.1:  # Загромождённая
    max_iterations = 3000
    step_size = 3.0
    replan_rate = 2.0
elif obstacle_density > 0.05:  # Умеренная
    max_iterations = 2000
    step_size = 5.0
    replan_rate = 1.0
else:  # Разреженная
    max_iterations = 1000
    step_size = 8.0
    replan_rate = 0.5
```

## Советы по отладке

### Проблема: Планирование занимает слишком много времени (>500 мс)

**Решения:**
- Уменьшить `max_iterations` до 1000-1500
- Увеличить `step_size` до 7-8 м
- Уменьшить `search_radius` до 10-12 м
- Проверить чрезмерное количество точек препятствий в облаке точек

### Проблема: Пути сталкиваются с препятствиями

**Решения:**
- Увеличить `obstacle_clearance` до 4-5 м
- Проверить точность облака точек LiDAR
- Проверить `obstacle_inflation` в детекторе препятствий (должно быть 3.0 м)
- Уменьшить `step_size` для более точной проверки столкновений

### Проблема: Путь не найден

**Решения:**
- Увеличить `max_iterations` до 3000-5000
- Увеличить `planning_horizon` (может потребоваться промежуточная цель)
- Уменьшить `min_turn_radius`, если кинематически безопасно
- Проверить, достижима ли цель с текущими ограничениями
- Увеличить `goal_tolerance` для навигации по путевым точкам

### Проблема: Пути слишком зубчатые/не гладкие

**Решения:**
- Увеличить `search_radius` до 20-25 м
- Увеличить `min_turn_radius` до 25-30 м
- Уменьшить `max_climb_angle` до 15°
- Реализовать дополнительную постобработку сглаживания пути

### Проблема: Высокая загрузка ЦП (>50%)

**Решения:**
- Уменьшить `max_iterations` до 1500
- Увеличить `step_size` до 6-8 м
- Уменьшить `replan_rate` до 0.5-1.0 Гц
- Проредить облако точек LiDAR перед планированием
- Использовать пространственное хеширование для обнаружения столкновений

## Рекомендации по тестированию

### Фаза 1: Симуляция (Gazebo)
1. Начать с параметров по умолчанию
2. Добавить простые препятствия (стены, коробки)
3. Проверить, что пути свободны от столкновений и гладкие
4. Измерить время планирования и использование ресурсов

### Фаза 2: Сложная симуляция
1. Добавить плотные поля препятствий
2. Протестировать различные конфигурации (загромождённая, открытая, смешанная)
3. Проверить кинодинамические ограничения (радиус поворота, угол набора высоты)
4. Протестировать аварийные сценарии

### Фаза 3: Тестирование на оборудовании
1. Начать в открытой среде с параметрами по умолчанию
2. Проверить точность обнаружения препятствий
3. Настроить `obstacle_clearance` с учётом реального шума датчиков
4. Протестировать на различных скоростях
5. Постепенно увеличивать сложность среды

### Фаза 4: Тестирование миссий
1. Полные профили миссий с путевыми точками
2. Различные погодные условия
3. Дневные/ночные операции (производительность LiDAR)
4. Граничные случаи (узкие проходы, эстакады и т.д.)
